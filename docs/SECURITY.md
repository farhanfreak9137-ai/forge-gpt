# ForgeAgent V1 Security Model & Sandboxing

## 1. Untrusted Boundaries

In ForgeAgent V1, **all external inputs are treated as untrusted**:
1. **AI Model Outputs**: Any suggestion, code change, or command generated by an AI provider is treated as unverified data. It is never executed directly without validation.
2. **Project Code & File Contents**: Source code may contain adversarial prompt injection or traversal attempts.
3. **Terminal Outputs & Diagnostics**: Standard output and error streams are sanitized and secret-redacted before inclusion in context prompts.

---

## 2. Supervised Autonomy & Permissions

ForgeAgent divides all system actions into three strict permission tiers:

### Tier 1: Automatically Allowed
- Reading authorized workspace project files.
- Inspecting Git metadata and history.
- Scanning project directory structure.
- Formulating task plans with the configured AI provider.
- Running safe pre-flight checks and linters.

### Tier 2: Allowed Within an Approved Task
- Creating new files inside the isolated workspace directory.
- Editing existing authorized files within workspace boundaries.
- Applying validated unified diffs with sha256 hash verification.
- Executing allowlisted test commands (`python -m pytest`, `npm test`).
- Creating transactional Git checkpoints.
- Executing bounded repairs up to configured retry limits (default 4).

### Tier 3: Explicit Approval Required
- Deleting files (`ChangeOperation.DELETE`).
- Modifying sensitive configuration files (`.env`, `docker-compose.yml`, `Dockerfile`).
- Installing or updating packages (`npm install`, `pip install`, `yarn add`).
- Executing unapproved commands outside the allowlist.
- Remote Git operations (`git push`, destructive hard resets).
- Switching AI reasoning providers.

---

## 3. Filesystem Sandboxing & Traversal Defenses

The `SafeFileManager` enforces the following checks on every file operation:
- **Canonical Resolution**: Resolves all relative paths against `workspace.resolve()`.
- **Directory Traversal Rejection**: Rejects any path containing `..` elements.
- **Root Escape Check**: Enforces `target_path.relative_to(workspace_path)`.
- **Symlink Protection**: If the target is a symbolic link, verifies that its resolved destination still resides within the workspace boundary.
- **Atomic Writes**: Writes changes to temporary files in the target directory and executes atomic replacement (`os.replace`) to prevent file corruption during system crashes.

---

## 4. Execution Sandbox

### Windows Native Mode
- Strict command allowlist: `git`, `python`, `py`, `pytest`, `node`, `npm`, `npx`, `pip`, `uv`, `cargo`, `dotnet`, `go`, `cmd`, `powershell`.
- Rejects shell operator chaining (`&&`, `||`, `;`, `|`, `` ` ``, `$()`).
- Bounded process execution timeouts (default 60 seconds).
- Explicit working directory confinement to the workspace root.

### Docker Mode
- Containerized execution providing isolated namespaces for processes, network, and filesystem.
- No mounting of host credentials or Docker socket into the task container.

---

## 5. Secret Redaction & Loopback Binding

- **Local Loopback**: By default, the FastAPI server and WebSocket endpoints bind strictly to `127.0.0.1`.
- **Secret Redaction**: `ContextBuilder` strips patterns matching API keys (`sk-...`, `ghp_...`, `AIza...`), tokens, and passwords from prompts before dispatch to external AI providers.
- **Emergency Stop**: Prominent button in the dashboard and API endpoint immediately halts active operations and blocks any pending modifications.
